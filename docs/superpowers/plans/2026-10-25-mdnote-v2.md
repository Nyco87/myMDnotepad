# MDnote v2 — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Faire évoluer MDnote v1 avec quatre groupes de changements :
- retouches suite au test utilisateur : zone uniforme, sans Mica, icône Symboles, accent Windows, surlignage ;
- blocs d'alerte GitHub ;
- schémas mermaid avec atelier à briques (camembert, flux, états, Gantt) ;
- menu « / » ;
- correctifs de sûreté hérités de la v1.

**Architecture :** On reste sur la base v1 (Tauri 2, ProseMirror, sérialiseur maison qui conserve le brut tel quel). Les ajouts se répartissent ainsi :
- **Rust :** lecture de l'accent Windows (WinRT `UISettings`) avec un événement à chaud, et un code d'erreur `NOT_FOUND`.
- **Schéma de l'éditeur :** une marque `highlight` et un nœud `alert`.
- **Module `src/diagram/` :** le rendu mermaid chargé à la demande, des modèles par type (aller-retour strict code ↔ briques) et l'atelier.
- **Menu « / » :** un plugin ProseMirror.

**Tech Stack :** l'existant v1, plus `mermaid@11` (import dynamique, découpé par Vite) et la crate `windows` (feature `UI_ViewManagement`, `Foundation`).

**Spec :** `docs/superpowers/specs/2026-10-25-mdnote-v2-design.md`. La spec v1 `docs/superpowers/specs/2026-10-24-mdnote-design.md` reste en vigueur.

## Contraintes globales

- Toutes les garanties v1 restent valables :
  - aucune perte de données ;
  - ouvrir une note ne l'écrit jamais ;
  - Markdown « pretty » idempotent ;
  - le Markdown non pris en charge est conservé octet pour octet ;
  - démarrage < 1 s mesuré avec `scripts/measure-startup.ps1` ;
  - `.exe` unique via `npx tauri build --no-bundle` ;
  - textes de l'interface en français ;
  - Windows 11 uniquement.
- Branche de travail `feat/mdnote-v2`, créée depuis `feat/mdnote-v1` (HEAD `06da1b0`).
- Les 280 tests vitest et 46 tests cargo existants doivent continuer à passer.
- mermaid n'est **jamais** chargé sur le chemin critique du démarrage (`markReady` se déclenche avant tout import de mermaid).
- Couleurs fixes des alertes :
  - Note `#4493f8` ℹ️
  - Astuce `#3fb950` 💡
  - Important `#ab7df8` ❗
  - Attention `#d29922` ⚠️
  - Danger `#f85149` 🔴
- Surlignage : fond `#9a6700`, texte `#fff3c4`.
- Couleur d'accent de repli : `#60cdff`.

## Points d'attention (Review Focus)

1. **Code mermaid invalide** tapé à la main, ou type inconnu : un cadre d'erreur discret affiche le message et le code, le texte du bloc n'est jamais modifié, rien ne plante. → Task 6.
2. **`/` dans du texte ordinaire** (`https://a/b`, `24/10`, `C:/x`, `et/ou`) ou dans du code : le menu ne s'ouvre pas. → Task 10.
3. **Alerte inconnue ou en minuscules** (`> [!FOO]`, `> [!note]`) : `[!FOO]` reste une citation intacte, et `[!note]` est réécrit à l'identique tant qu'on ne touche pas à l'alerte. → Task 5.
4. **`==` hors surlignage** (`a==b`, `if x == y`, `` `a==b` ``, bloc de code) : reste littéral, aller-retour identique. → Task 4.
5. **Note pleine de schémas à l'ouverture :** le démarrage reste < 1 s, car les schémas se dessinent après `markReady`, un par un, sans geler la saisie. → Task 11.
