# MDnote — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Construire MDnote, un éditeur de notes Markdown WYSIWYG (style Typora) livré en un seul `.exe` Windows 11 portable, sombre et acrylique, qui lit et écrit de vrais fichiers `.md` « pretty ».

**Architecture :** Application Tauri 2. Le côté Rust (`src-tauri/`) possède tout ce qui touche au disque et à la fenêtre : réglages portables, arborescence, lecture et écriture atomiques, opérations sur les fichiers (images comprises), surveillance du dossier, effet acrylique/Mica. Le côté TypeScript (`src/`, Vite, sans framework pour démarrer vite) affiche l'interface. L'éditeur repose directement sur ProseMirror, avec un parseur markdown-it et un sérialiseur maison qui garantissent le format « pretty » et la conservation à l'identique du Markdown non pris en charge.

**Tech Stack :** Tauri 2, Rust stable (crates : `serde`, `notify-debouncer-mini`, `trash`, `window-vibrancy`, `regex`, `tempfile` en dev), TypeScript, Vite, `prosemirror-*` (`model`, `state`, `view`, `inputrules`, `keymap`, `commands`, `history`, `tables`, `schema-list`), `markdown-it` + `markdown-it-task-lists`, `@tauri-apps/api`, `@tauri-apps/plugin-dialog`, Vitest + jsdom.

**Spec :** `docs/superpowers/specs/2026-10-24-mdnote-design.md`

## Contraintes globales

- Windows 11 uniquement. Le livrable est un `.exe` unique produit par `npx tauri build --no-bundle` (`src-tauri/target/release/mdnote.exe`), sans installateur, sans signature de code, sans droits administrateur, sans réseau au runtime.
- Mode sombre uniquement, style Fluent. Effet de fenêtre : acrylique par défaut, Mica en repli (réglage `window_effect`).
- Les notes sont de vrais fichiers `.md` sous un dossier racine choisi par l'utilisateur. Pas de base de données.
- Réglages dans `mdnote.settings.json` à côté du `.exe`. Si cet emplacement n'est pas inscriptible, ils vont dans `%APPDATA%\MDnote\mdnote.settings.json`.
- **Aucune suppression définitive :** toute suppression passe par la Corbeille Windows.
- **Aucune perte de données :** ouvrir une note ne l'écrit jamais. On n'enregistre qu'après une vraie modification. Le Markdown non pris en charge est conservé octet pour octet.
- Markdown « pretty » : titres `#`, une ligne vide entre blocs, puces `-`, listes numérotées `1.`, gras `**`, italique `*`, barré `~~`, code clôturé par ```` ``` ````, tableaux aux colonnes alignées, un seul `\n` final, UTF-8, fins de ligne `\n`, sérialisation idempotente.
- Démarrage : fenêtre utilisable en **moins de 1 s**, mesuré.
- Tous les chemins échangés entre Rust et TS sont **relatifs à la racine**, avec des `/`. Rust refuse tout chemin qui sort de la racine.
- Textes de l'interface en français.

## Points d'attention (Review Focus)

1. **Note modifiée hors de l'app pendant qu'on la modifie** (OneDrive, VS Code). Sans modification locale en attente, on recharge. Avec une modification en attente, on enregistre la version de l'utilisateur et on garde la version externe dans `<nom> (conflit AAAA-MM-JJ HHmm).md`, sans rien écraser en silence. → Task 11.
2. **Nom de fichier interdit sous Windows** (`<>:"/\|?*`, noms réservés `CON`, `NUL`…, point ou espace final), à la création ou au renommage : on refuse avec un message clair, sans plantage ni fichier fantôme. → Task 3.
3. **Nom déjà pris** lors d'une création, d'un renommage ou d'un déplacement : création et déplacement suffixent automatiquement (`Nouvelle note 2`), le renommage refuse avec un message. → Task 3.
4. **Dossier racine introuvable au lancement** (clé débranchée, dossier supprimé) : l'écran de choix du dossier réapparaît avec un message, sans plantage. → Task 13.
5. **Fermeture de l'app avec un enregistrement en attente** (pendant le délai de 400 ms) : on vide la file d'enregistrement avant de fermer, aucune frappe n'est perdue. → Task 12.
